# R-Shell 桌面 GUI — 命令块终端原型（Block Terminal · 方案 A）

> 状态:原型(Stage 9)| 设计语言见 [03-UI设计规范](03-UI设计规范.md) | 架构见 [02-架构设计](02-架构设计.md) | 进度见 [进度.md](进度.md)
> 代号:**Block Terminal**（命令块式 / Warp · 聊天流）。

---

## 1. 为什么做(动机)

现有「终端」是传统的**全屏 PTY + xterm** 模拟器(`features/terminal/`):一整块字符网格,提示符 / 命令 / 输出混在一起、靠 ANSI 重绘,搜一段历史输出要在回滚缓冲里捞。

用户选定 **方案 A：命令块式**——

- **每条命令带自己的输出成「一个块」**(命令头 + 输出体 + 状态/耗时/退出码)。
- **整体从上往下读**(像聊天流 / Warp),新块追加到底部、自动滚到底。
- **输入框钉在底部**,回车提交,↑/↓ 翻命令历史。

价值:输出**天然分段**(可单独复制/折叠/重跑某块)、**退出码一眼可见**、**`cd` 在块之间保持**、不被全屏程序的重绘干扰。本阶段先做**正式原型**验证这套交互方向,**不替换**现有 xterm 终端(并存,新增导航入口)。

---

## 2. 执行模型(关键决策)

命令块**不是**交互式 PTY,而是「**一条命令 → 跑完 → 捕获完整输出成块**」。难点是:每条命令各自起一个 exec 通道(SSH)/ 子进程(ADB / 本机),通道之间**不共享 shell 状态**,于是 `cd /tmp` 后下一条 `ls` 不在 `/tmp`。

### 2.1 POSIX sentinel 包装(cwd 跟踪 + 退出码 + stderr)

对每条用户命令包装成一小段 POSIX shell:

```sh
{ cd <CWD> 2>/dev/null; <COMMAND>; } 2>&1; __rsrc=$?; printf '\036%s\036%s\036' "$__rsrc" "$(pwd)"
```

- `cd <CWD>`:把上一块结束时记下的工作目录带进来 ⇒ **`cd` 在块之间持久**(`{ }` 组在**当前** shell 执行,用户命令里的 `cd` 也会改外层 `$(pwd)`)。
- `{ …; } 2>&1`:把组内 **stderr 合并进 stdout**。SSH 的 `execute_command` 只捕获 stdout(`ExtendedData`/stderr 被丢弃),不合并就看不到报错。
- `__rsrc=$?`:抓**用户命令**的真实退出码(组的退出码 = 组内最后一条命令)。
- `printf '\036…\036…\036'`:用 **RS(0x1E)** 作分隔符,在输出尾部打一行「`退出码`、`新 pwd`」哨兵。`printf` 自身恒退出 0 ⇒ **SSH/ADB 看到整条命令成功**、原样回传全部输出(真实退出码从哨兵里解析,不再依赖通道退出码)。

### 2.2 解析(`parse_outcome`)

原始输出尾部形如 `…body…\x1e<rc>\x1e<pwd>\x1e`。按 `\x1e` 切分,取末尾三段拿 `rc` / `pwd`,其余为 `body`:

- 命中哨兵:`exit_code` = 解析的 rc,`cwd` = pwd,`had_marker = true`。
- 未命中(如 **Windows PowerShell** 不认这套 sh 语法):`body` = 原始输出、`exit_code = -1`、`cwd` 不变、`had_marker = false`——**优雅降级**:输出照常显示,只是没有退出码 / cwd 跟踪。

> 原型范围:cwd 跟踪 + 退出码以 **POSIX 远端**(Linux SSH / Android ADB / 本机 macOS·Linux)为准。Windows(PowerShell)留作后续(需另写一套 PS 哨兵)。

### 2.3 两条执行路径(复用既有能力,core 几乎不动)

| 目标 | 实现 | 复用 |
| --- | --- | --- |
| **远程**(SSH / ADB) | bridge `block_run_remote` → `ensure_session` → `manager().execute_command(id, wrap_posix(cwd, cmd))` → `parse_outcome` | 完全复用 `native_backend` 的 `execute_command`(SSH/ADB 透明分派);**core 无需新增执行通道** |
| **本机**(运行 GUI 的电脑) | bridge `block_run_local` → `core::blockexec::run_local`(`$SHELL -c <wrapped>`,`tokio::process`) | 让用户**无需任何服务器**就能在 Mac 上立刻试 |

wrap / parse / run_local 三个纯逻辑放 **core 新模块 `blockexec.rs`**(可单测、CLI/GUI 共享),bridge 只做薄封装。

### 2.4 暂不做(原型边界)

- **流式输出**:本版是「跑完才出块」(阻塞 request/response),长命令期间块内转圈。流式(边跑边追加)是首要后续增强(可仿 PTY 的 `StreamSink` 范式)。
- **交互式 / 全屏程序**(`top`/`vim`/`ssh`/`sudo` 密码交互):命令块不接管 TTY,这类仍走现有 xterm 终端。
- **管道分页 / TTY 检测**:命令在无 TTY 的 exec 通道执行(`isatty=false`),与 PTY 行为可能略有差异(如颜色被部分程序关掉)。

## 3. 组件划分(Flutter,`features/blockterm/`)

| 文件 | 职责 |
| --- | --- |
| `block_models.dart` | `CommandBlock`(命令/cwd/输出/退出码/状态/耗时)+ `BlockStatus` 枚举 + 纯展示辅助(`promptDir` 把 home 缩成 `~`、状态色/标签) |
| `block_repository.dart` | 封装 frb `blockRunRemote` / `blockRunLocal`,UI 不直接碰 frb |
| `block_terminal_controller.dart` | `ChangeNotifier`:目标(本机 / 某连接)、当前 cwd、块列表、命令历史、`run()`(追加运行中块 → await → 回填输出/退出码/cwd/耗时)、`clear()` |
| `block_terminal_panel.dart` | 整页布局:顶栏(目标选择 + cwd + 清空)+ 块流(`ListView`,上→下,自动滚底)+ 底部输入条(钉底) |
| `widgets/command_block_tile.dart` | 单个命令块:头(状态点 + `cwd $ command` + 耗时 + 退出码 chip + 复制/重跑)+ 体(等宽、可选中、可折叠) |
| `widgets/block_input_bar.dart` | 钉底输入条:提示符字形 + 等宽 `TextField`(回车提交、↑/↓ 历史)+ 运行按钮 + 忙碌态 |

状态延续项目一贯的轻量 `ChangeNotifier`(Riverpod 继续推迟,与前序阶段一致)。所有颜色/间距走 `AppColors`/`AppSpacing` token,不写死 hex。

接线:`app_scaffold` 图标导航新增 **「命令块」**(index 5,`Icons.view_agenda_outlined`),整页占满(无监控侧栏);默认目标 = **本机**,可在顶栏切到任一已保存连接。**不动**现有 `features/terminal/`。

## 4. 数据流

```text
输入框回车
  → BlockTerminalController.run(cmd)
      ├─ 追加 CommandBlock(status=running, cwd=当前)         → notifyListeners(立刻出块)
      ├─ 本机?  repo.runLocal(cmd, cwd)
      │  远程?  repo.runRemote(connId, cmd, cwd)
      │         └─ bridge: ensure_session → execute_command(wrap_posix) → parse_outcome
      └─ 回填 block.output / exitCode / status / duration;controller.cwd = 结果.cwd → notify
  → 面板自动滚到底
```
