# R-Shell 桌面 GUI 架构设计(Flutter + Rust 核心)

> 状态:设计中 | 选型见 [01](01-GUI技术选型对比.md) | 进度见 [进度.md](进度.md)
> 决策:UI 用 **Flutter**,通过 **flutter_rust_bridge** 调用已抽出的 **`r-shell-core`**(Rust)。

## 1. 总览

GUI 不重写任何 SSH/SFTP/监控/MCP 逻辑,而是把 Stage 0 抽出的 `r-shell-core` 当作唯一事实来源,Flutter 只负责界面与交互。三层:

```text
┌─────────────────────────────────────────────┐
│  Flutter (Dart) UI                            │  界面 / 状态 / 交互(本设计第 6、7 节)
│  连接树 · 多标签终端 · SFTP 双栏 · 监控 · MCP │
└───────────────┬─────────────────────────────┘
                │  flutter_rust_bridge(FFI,异步 + Stream)
┌───────────────▼─────────────────────────────┐
│  r-shell-bridge (Rust, cdylib)                │  薄封装:把 core 的能力暴露成 GUI 友好的 API
└───────────────┬─────────────────────────────┘
                │  普通 Rust 调用(同 crate workspace)
┌───────────────▼─────────────────────────────┐
│  r-shell-core (Rust lib)  ← 已完成 Stage 0    │  ssh / native_backend / monitor / mcp / model / storage
└───────────────┬─────────────────────────────┘
                │ russh / russh-sftp / axum / rmcp / tokio
                ▼
        远程服务器(SSH / SFTP)· 本地 MCP 端点
```

CLI(`r-shell`)与 GUI 共用同一个 `r-shell-core`,任何核心改动两端同时受益。

## 3. 关键依赖

- Flutter 3.44 / Dart 3.12(已就绪)。状态管理:**Riverpod**(测试友好、依赖注入清晰)。
- 终端组件:**`xterm`(xterm.dart)** —— VT 解析 + 渲染 + 选择/复制。
- 桥接:**`flutter_rust_bridge` v2** + `flutter_rust_bridge_codegen`。
- 窗口/系统:`window_manager`(窗口控制)、`tray_manager`(托盘,设置里「最小化到托盘」需要)、`file_selector`/拖拽(`super_drag_and_drop`)用于 SFTP 上传。
- 图表(监控迷你折线):`fl_chart`。

## 4. flutter_rust_bridge 接口设计(GUI 面向的 API)

`r-shell-bridge` 把 `r-shell-core` 包装成一组 GUI 友好函数;**异步用 frb 的 async,持续数据(PTY 输出 / 传输进度 / 监控)用 `StreamSink`**。下列为意图签名(Stage 1 落地时定稿):

```rust
// 连接管理(落在 core::storage + core::model)
pub fn list_connections() -> Vec<ConnectionDto>;
pub fn create_connection(input: ConnectionInput) -> ConnectionDto;
pub fn update_connection(id: String, input: ConnectionInput) -> ConnectionDto;
pub fn delete_connection(id: String);

// 会话(落在 core::native_backend::NativeConnectionManager)
pub async fn session_open(target: SessionTarget) -> SessionId;   // 复用/新建,返回 id
pub async fn session_close(id: SessionId);
pub async fn session_status(id: SessionId) -> SessionState;

// 命令执行(命令面板 / exec)
pub async fn exec(id: SessionId, command: String) -> ExecResult;

// 交互式终端(PTY)—— 流式
pub async fn pty_open(id: SessionId, cols: u16, rows: u16, sink: StreamSink<Vec<u8>>) -> PtyId;
pub async fn pty_write(pty: PtyId, data: Vec<u8>);
pub async fn pty_resize(pty: PtyId, cols: u16, rows: u16);
pub async fn pty_close(pty: PtyId);

// 文件管理(SFTP)—— 列表同步、传输流式带进度
pub async fn sftp_list(id: SessionId, path: String) -> Vec<RemoteFileEntry>;
pub async fn sftp_upload(id: SessionId, local: String, remote: String, sink: StreamSink<Progress>);
pub async fn sftp_download(id: SessionId, remote: String, local: String, sink: StreamSink<Progress>);

// 监控仪表盘 —— 周期推送
pub async fn stats_stream(id: SessionId, interval_ms: u64, sink: StreamSink<SystemStats>) -> StatsHandle;
pub async fn stats_stop(handle: StatsHandle);

// MCP 服务器(落在 core::mcp)
pub async fn mcp_start(bind: String, port: u16) -> McpStatus;  // 默认 127.0.0.1:9123
pub async fn mcp_stop();
pub fn mcp_status() -> McpStatus;     // 运行态 / 端口 / 运行时长 / 工具清单
```

DTO 直接复用或镜像 core 的 `SavedConnection` / `ConnectionStatus` / `RemoteFileEntry` / `SystemStats`,**密码/私钥永不回传到 Dart**(沿用 core 的脱敏策略,只给 `has_password` 布尔)。

## 5. 终端方案

- Dart 侧:`xterm` 的 `Terminal` 组件负责显示与输入。
- 输出:`pty_open` 的 `StreamSink<Vec<u8>>` 把 core PTY 的字节流推给 Dart,`terminal.write(bytes)`。
- 输入:`terminal.onOutput` → `pty_write`。
- 尺寸:`TerminalView` resize → `pty_resize`。
- 多标签:每个标签一个 `(SessionId, PtyId, Terminal)` 三元组,标签关闭即 `pty_close`。

## 6. UI 规格(以用户提供的设计稿为基准)

主窗口三栏布局:

- **左·导航 + 连接树**:竖排导航图标(连接/终端/文件/监控/MCP/设置);搜索框;按分组折叠的连接树(生产/测试/开发/本地),每项带状态点(绿=在线/红=断开/灰=未连);底部「添加 / 编辑 / 设置」。
- **中·终端 + 文件**:上半为**多标签终端**(标签可关、可新建;工具栏:重连/复制/粘贴/清屏/更多);下半为 **SFTP 双栏**(左远程、右本地,列:名称/大小/类型/修改时间,中间 ←/→ 传输按钮;「传输队列」页签;底部连接延迟与 SFTP 状态)。
- **右·服务器监控**:时间范围下拉 + 自动刷新开关;CPU / 内存 / 负载 卡片(含迷你折线);磁盘 / 网络 卡片;进程 Top5 表(PID/名称/CPU%/内存%)。

弹窗 / 面板:

- **连接编辑**:页签 常规/SSH/高级/备注;字段 名称、分组、主机、端口、用户名、密码、认证方式、图标;取消/保存。
- **命令面板(Exec)**:搜索框 + 常用/历史/收藏 页签 + 命令列表,Enter 执行(对接 `exec`)。
- **文件上传(拖拽)**:目标目录 + 文件列表(名称/大小/状态:上传中%/完成/等待)+ 总进度与剩余时间 + 取消全部/继续。
- **MCP 面板**:开关 + 监听地址/端口 + 运行状态与运行时长 + 停止/重启 + 可用工具清单 + 访问地址。
- **设置**:页签 通用/外观/终端/文件传输/监控/快捷键/关于;启动恢复上次工作区、开机自启、最小化/退出到托盘、语言、主题。

主题:深色为主(对齐设计稿),抽出统一的 `AppTheme`(颜色/间距/圆角/字体),组件复用。

> ⚠️ 设计稿与现状的两处差异,以**核心现状**为准并标注:
> 1. 稿中 MCP 端口为 `6200`,核心默认 `127.0.0.1:9123`。GUI 做成**可配置**,默认 9123。
> 2. 稿中 MCP「可用工具」是示意(connections/shell/exec/ls/...)。实际以 core 暴露的工具为准(`ssh_session_open` / `ssh_exec` / `ssh_read_file` / `ssh_write_file` / `ssh_list_dir` / `ssh_sessions_list` / `ssh_session_close` + `r_shell_ssh_connection_*`),面板动态读取 `mcp_status()`。

## 7. 状态管理与数据流

- **Riverpod** 管理:连接列表、会话表、各终端标签、SFTP 两侧目录、监控数据流、MCP 状态。
- `bridge/` 提供 Repository 封装 frb 调用;`features/*` 通过 provider 消费,UI 不直接碰 frb。
- 长生命周期资源(PTY、stats stream、MCP)由 provider 持有,页面切换不中断;窗口关闭时统一 dispose → 调 `*_close/stop`。

## 8. 线程 / 异步模型

- Rust 侧由 frb 托管一个 `tokio` 运行时;core 本就是 `tokio` 异步。
- 流式数据(PTY/进度/监控)用 `StreamSink` 单向推送,避免 Dart 轮询。
- 取消:每个流持有 `CancellationToken`(core 已用),Dart 调对应 `*_close/stop` 触发。

## 9. 打包

- `flutter build macos / windows / linux`;frb 的 Rust 产物随 Flutter 构建编译(`cargokit`/`flutter_rust_bridge` 集成)。
- 复用并扩展现有 `packaging/`(macOS DMG、Windows NSIS),新增 Linux(AppImage/deb)。
- GUI 的 CI 与现有 CLI release workflow 并存(分开 job)。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| PTY 字节流性能/乱码 | 用 `xterm.dart` 成熟解析;字节流不做 Dart 侧转码,原样喂入 |
| frb 异步流背压 | `StreamSink` + 合理 buffer;监控降频(默认 1s) |
| 凭据泄漏到 UI 层 | 沿用 core 脱敏;DTO 不含明文密码/私钥 |
| 多平台终端/键位差异 | 早期就在三平台冒烟;`crossterm` 仅 CLI 用,GUI 不依赖 |
| 设计稿与核心能力不一致 | 以 core 为准并在面板动态读取真实状态(见第 6 节注) |
